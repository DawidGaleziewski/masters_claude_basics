# How cloude handles requests?
It will assemble these things into one big requests

Example request
```json
{
    "model": "opus",
  "messages": [
    {
      "role": "user",
      "content": "Write a function that returns the sum of two numbers"
    }
  ],
  "tools": [
    {
      "type": "function"
    },
}
```
IMPORTANT: model does not understand json. It understands tokens only. 

## Tool schema
Bash, Edit, Read, Agent, WebFetch, Write, mcp-*
Every action that model can make.
Model itself cannot run the tool. But it can executte it via harness

## System prompt
Tone, Env, Security rules, code conventions. System prompt will be prioritiezed (in some examples, not all)

## Messages
- Claude.md (only first msg)
- available skills (name and description)
- prompt


# Reasononing
Once model recives call. It can start reasoniong like
"Hmm... user wants X added in utils.ts"
"I do not have the signature. I need to read the file first"
"I see I have access to READ tool call. I will use that"

# Tool calling
API (model) needs to respond with tool call. For harness to start executing it.

## Assistant
```json
{
  "type": "tool_call",
  "name": "Read",
  "input": {
    "file_path": "utils.ts"
  }
}
```

After that msg is again composed. Harness will add assistent tool call and its result

```json
{
    "model": "opus",
  "messages": [
    {
      "role": "user",
      "content": "Write a function that returns the sum of two numbers"
    },
    {
      "type": "tool_call",
      "name": "Read",
      "input": {
        "file_path": "utils.ts"
      }
    },
    {
      // tool, call reasults here? I.e content resoult
    }
},
  ],
  "tools": [
    {
      "type": "function"
    },
}
```
# Agentic loop
Concept of agent going back and forth with the model.
Harness will ping pong with model i.e. 
1. Harness -> msg
2. Model -> tool call for Read
3. Harness -> tool call result i.e error with specifics
4. Model -> New tool call 
5. Harness -> New tool call result
6. Model -> msg without tool call (signal to harness nothing else needs to be done)
